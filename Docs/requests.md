# 요청 기록

## 2026-05-31 21:00:00 (elapsed 00:00:00)

- `lookandfeel.png`를 기반으로 UI 위젯 구현 계획 전체를 수행한다.
- 사용자는 제안된 방향을 승인했다. `lookandfeel.png`를 원본 시각 SSOT로 취급하고, 여기서 구현용 토큰을 파생한 뒤, 실제 UMG 위젯들이 사용하는 UE 쪽 공통 스타일 레이어를 만든다.
- 전체 시안을 이미지 한 장으로 박아 넣지 않고, 대부분의 UI는 UMG 기본 위젯과 C++ 헬퍼로 구성한다.
- `Docs/ui-tokens.md`를 파생 구현 계약 문서로 만든다. 이 문서는 팔레트, 의미 색상, 라운드, 간격, 버튼 높이, 폰트 계층, 컴포넌트 패턴, 구현 메모를 기록한다. 이 문서가 `lookandfeel.png`와 충돌하면 사용자가 스타일 계약 변경을 명시적으로 승인하지 않는 한 `lookandfeel.png`가 우선한다.
- UI 키트 데모와 팝업 동작을 위한 C++/UMG 위젯 클래스를 추가한다.
- 레벨에서 데모 위젯을 띄울 수 있도록 시작 Actor 또는 동등한 테스트 진입점을 추가한다.
- 결정적으로 재사용 가능한 비트맵은 `lookandfeel.png`에서 크롭한다. 크롭이 어렵거나 UMG 기본 위젯으로 표현하기 어려운 누락 래스터 에셋만 이미지 생성을 사용한다.
- 팝업 데모 상호작용은 자체 완결형이어야 한다. 버튼은 동작하는 척 시각적으로 시뮬레이션하고 팝업을 닫을 수 있지만, 외부 게임 상태를 변경하면 안 된다.
- 필요하면 병렬 에이전트를 사용한다. 이번 작업은 토큰 사용량보다 리드타임이 더 중요하다.

- 병렬 에이전트를 사용해 자동화 테스트 구현을 별도 작업으로 진행한다.

## 2026-05-31 21:48:14 (elapsed 00:48:14)

- `lookandfeel.png`를 통째로 올리는 방식이 아니라, 기능별로 분할 가능한 UMG 위젯 단위로 임의 판단해 작업한다.
- 데모 화면은 여러 테스트용 위젯을 조립하는 역할로 줄이고, 각 기능 영역은 독립적인 위젯 클래스로 분리한다.
- 특히 퀘스트 영역은 고정 텍스트가 아니라 임의의 여러 퀘스트 데이터를 가지고, 진행/완료 가능/완료/실패 같은 상태가 버튼 상호작용으로 바뀌도록 만든다.
- 인벤토리도 화면 일부를 통째로 크롭한 이미지를 붙이는 방식이 아니라, 개별 슬롯과 아이템 데이터를 UMG로 구성한다.

## 2026-05-31 21:54:55 (elapsed 00:54:55)

- 이번 시도에서는 스크롤 박스와 슬라이더처럼 사용자 입력을 받는 UI가 실제 UMG 위젯 이벤트로 동작해야 한다.
- 구현 시간이 오래 걸려도 괜찮으니 정적 시안 재현보다 상호작용 품질을 우선한다.
- 퀘스트 목록, 인벤토리 목록, 설정/컨트롤 영역은 단순 표시가 아니라 스크롤, 선택 변경, 값 변경, 상태 갱신을 확인할 수 있는 테스트 위젯으로 만든다.
