# 질문 기록

## 2026-05-31 20:56:04 (elapsed 00:00:00)

**질문:** 이미지 시안을 기반으로 위젯들을 만들 때, 필요한 이미지를 크롭하거나 `imagegen`으로 생성하는 작업은 어떤 식으로 할 것인가?

**답변:** `lookandfeel.png`를 SSOT로 보고 단계적으로 진행한다. 먼저 재사용 가능한 UI 치수와 색상을 뽑고, 대부분의 UI는 UMG 기본 위젯으로 만든다. 실제 그림이 필요한 구체적인 비트맵만 시안에서 크롭하고, 부족한 프로젝트용 래스터 에셋은 필요할 때 내장 `image_gen` 경로로 생성한다. 최종 에셋은 프로젝트 내부에 저장하고, 마지막에 시작 위젯을 레벨 테스트 흐름에 연결한다.

## 2026-05-31 20:57:38 (elapsed 00:00:00)

**질문:** UI 토큰 분석 단계의 최종 아웃풋은 무엇인가?

**답변:** 최종 산출물은 단순 분석 문서가 아니라 UE 쪽에서 재사용할 수 있는 UI 스타일 레이어다. 색상, 간격, 라운드, 폰트 크기, 버튼/상태 스타일을 코드 상수와 헬퍼로 만들고, 짧은 토큰 참조 문서도 함께 둔다. 실제 UMG 데모 위젯과 팝업 위젯은 이 토큰을 직접 사용한다.

## 2026-05-31 20:58:40 (elapsed 00:00:00)

**질문:** `ui-tokens.md`가 룩앤필을 강하게 제약하는 SSOT 성격이 맞는가?

**답변:** 원본 SSOT는 아니다. `lookandfeel.png`가 원본 시각 SSOT이고, `Docs/ui-tokens.md`는 거기서 파생된 구현 계약 문서다. 검토 후 확정되면 구현을 강하게 제약할 수 있지만, 둘이 충돌하면 사용자가 스타일 계약 변경을 명시적으로 승인하지 않는 한 `lookandfeel.png`가 우선한다.

## 2026-05-31 21:05:17 (elapsed 00:00:00)

**질문:** 크롭 중인 이미지들의 상태가 엉망인데 제대로 진행 중인가?

**답변:** 첫 크롭은 잘못됐다. 화면에 보이는 기준 좌표로 잘랐지만 실제 `lookandfeel.png` 원본 해상도는 `1536x1024`라 좌표가 어긋났다. 해당 크롭본은 사용하지 않고 원본 해상도 기준으로 다시 자른다.

## 2026-05-31 21:20:23 (elapsed 00:00:00)

**질문:** PIE 화면 자동 시각 검수가 가능한가?

**답변:** 가능하지만 사람 눈 수준의 미감 검수가 아니라 스크린샷 기반 자동 smoke test에 가깝다. UE 자동화 테스트나 standalone/editor 실행으로 화면을 렌더링한 뒤 스크린샷을 저장하고, 비어 있지 않은지, 주요 UI 영역의 색/픽셀 분포가 기대 범위인지, 크롭 에셋이 보이는지, 팝업 버튼 클릭 후 닫히는지 같은 조건을 검사할 수 있다.

## 2026-05-31 21:22:54 (elapsed 00:00:00)

**질문:** 현재 PIE에서 아무것도 보이지 않고 WASD로 카메라만 이동한다. 시동 위젯은 버튼이 달려서 다른 테스트용 위젯을 열어주는 위젯이어야 하는 것 아닌가?

**답변:** 맞다. 이전 구현은 레벨에 올릴 수 있는 부트스트랩 Actor와 바로 데모 UI를 띄우는 GameMode에 가까웠고, 사용자가 기대한 런처형 시동 위젯과 달랐다. 런처 버튼이 있는 `StartupWidget`을 추가하고, 맵 Actor나 GameMode에 덜 의존하도록 WorldSubsystem에서 자동 표시되게 수정한다.
